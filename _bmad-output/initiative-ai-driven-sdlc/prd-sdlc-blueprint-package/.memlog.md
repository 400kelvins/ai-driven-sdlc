- (event) Create run started; user intent: make what this repo built reusable as a package installable into existing repositories
- (decision) Audience: conference attendees install it into their own repos
- (decision) Scope: everything built here: human gates, gate review packs, CI human-gate check, spec-kit hooks, BMad setup, constitution
- (decision) Must be an experience: teaches purpose, how to use, what BMad does, what spec-kit does, how the AI talks to you (speech, quiz, diagrams)
- (decision) Any repository (Scrum works anywhere); not tied to a stack
- (decision) Distribution: npx package preferred over Claude Code plugin, to be AI-agnostic (Codex and other agents)
- (decision) Stakes: real product (maintained, versioned, documented); coaching path
- (event) Landscape research captured in addendum: CI gate is the only cross-agent enforcement point; invoke pinned BMad/spec-kit installers; no 'BMad' in product name
- (decision) Persona: software engineer with an existing repo, using Claude Code or Codex (both must be supported at launch)
- (decision) Flow: install -> agent initializes and scans repo for context -> user states feature intent -> story created on chosen tracker (GitHub first) -> one-time user auth -> implement -> review
- (decision) Core thesis: redefine AI-driven SDLC; not a huge code blob reviewed at the end; engage the human with quizzes, voice-over of what was implemented, ask for input
- (decision) Review is the hardest part: simplify it with context (module diagrams, how it works) - main effort goes here
- (decision) UJ-1 locked: Matthew, senior dev at Sorab, Claude Code; install -> init scan -> story on GitHub -> implement -> engaged review
- (decision) Review order: hear spoken summary -> call diagram (functions calling functions) -> task table -> guided per-file diff walkthrough -> quiz
- (decision) Quiz: multiple choice, plus typed answers for subjective questions
- (decision) Review time is not a goal; understanding is the success measure
- (decision) On No: code is not pushed; implementation stays on disk; agent asks why (approach change etc.) and what next
- (decision) Understanding = quiz correct + self-rated confidence + AI-graded own-words explanation; each wrong answer re-teaches that part (diagram/diff) and asks again
- (decision) No escape from the understanding loop for approval: no yes without understanding. [ASSUMPTION] Saying No stays available at any time
- (decision) Onboarding: after install, a tour / demo story; then guidance into the first real feature with a sample run shown
- (decision) Video: presenter records it; product only embeds/links it
- (decision) Demo story runs in the user's own repo on a disposable demo branch
- (decision) Feature groups F1-F9 confirmed: install, onboarding, repo init, stories+tracker, spec+implement, review experience, decision handling, enforcement, constitution
- (decision) Non-goal: multi-developer collaboration; a team acts as one reviewer for interaction
- (decision) Not in scope (not raised, confirmed good): deploy, retrospective
- (decision) Success = product stays alive: monthly product review held every month; outside contributors can push changes and open PRs to improve it
- (decision) Counter-metric/failure signal: monthly review skipped (not reviewed for months) = product failing, regardless of install numbers
- (decision) Telemetry v1: none sent; monthly review uses public signals only (npm downloads, stars, issues, PRs). Any future telemetry must be opt-in, asked once at install
- (decision) NFRs accepted: cross-OS voice (Linux browser fallback); Claude Code + Codex day 1; pinned BMad/spec-kit with contract tests before upgrades; never overwrite without asking, clean uninstall

- (decision) Human-yes proof: GitHub identity (PR comment/review) or signed commit, repo chooses; any code change after yes cancels it
